# 层级名翻译器 (Level Name Translator) v1.0.0

把 Unity 层级里那些日文 / 英文的对象名批量翻成中文，改模找部件的时候直观很多。
只处理你拖进来的对象，绝不动别的东西。

适用于 Unity 2019.3 以上，已在 **Unity 2022.3.22f1** 上编译验证通过。
纯 C#，无第三方 DLL，无运行时依赖（`Editor` 目录会自动识别为编辑器脚本）。

## 一、安装

**方式一（推荐）**：在 Unity 的 Project 窗口里右键 → `Import Package` → `Custom Package...`，
选 `LevelNameTranslator_v1.0.0.unitypackage`，点 Import。

**方式二**：直接把 `.unitypackage` 拖进 Project 窗口。

导入后菜单里会出现**两个入口**，点哪个都一样：

- **Tools → Level Name Translator (层级名翻译器)** ← 英文名排在 L 段，好找
- **Tools → 层级名翻译器** ← 中文名会被 Unity 排到菜单最下面

> 找不到菜单？看 Console 有没有红色编译错误。

---

## 二、第一次使用：填接口

打开窗口，展开顶部 **「▶ 接口设置（API Key / 模型）」**，填三样：

| 字段 | 填什么 |
|---|---|
| 接口地址 | `https://api.deepseek.com/chat/completions` |
| API Key | 你的 Key |
| 模型名 | `deepseek-flash`（或 `deepseek-v4-pro`） |

点 **「保存设置」**，再点 **「测试连接」**，日志出现「测试成功」即可。

### ⚠️ 最容易填错的两件事

1. **接口地址不是网页地址。**
   `https://platform.deepseek.com/api_keys` 是 Key 管理网页，填进去必然失败。
   必须是以 `/chat/completions` 结尾的 API 路径。
2. **模型名大小写敏感。**
   官方文档里是全小写的 `deepseek-flash` / `deepseek-v4-pro`。
   写成 `DeepSeek-V4.1-Flash` 这种会报模型不存在。

地址填错时工具会自动识别并改对，同时在日志里告诉你。也可以直接点 **「恢复默认地址」**（Key 不受影响）。

> Key 存在这台机器的 Unity 设置（EditorPrefs）里，**不写进工程目录**，不会被 git 提交。

## 三、日常使用

```
拖对象进窗口  →  开始翻译  →  逐条检查/手改  →  应用改名
```

### 1. 添加对象
在 Hierarchy 里选中要翻的节点，**直接拖进窗口**，或点「添加选中对象」。
可多选，也可分几次加。只处理你拖进来的，不做任何全工程扫描。

### 2. 翻译
点 **「开始翻译」**，工具会按顺序做：

1. 查**内置术语表**（`アウター=外套`、`スカート本体=裙子本体` 这类常见词，直接命中，不花钱）
2. 查**本机缓存**（同样的词不会重复请求，换工程也有效）
3. 剩下的才发给模型

译文出现在每行输入框里，**可以直接改**。改完不用额外保存，「应用改名」读的就是输入框里的值。

### 3. 安全预检（重要）
点 **「安全预检」**，会扫一遍工程，找出这些名字有没有被别的东西**按字符串**引用：

| 检查项 | 改名的后果 | 严重度 |
|---|---|---|
| 动画片段（`.anim`）的绑定路径 | 动画找不到对象，**动作直接失效** | 危险 |
| 代码里的 `Find("名字")` | 运行时找不到，功能静默坏掉 | 危险 |
| 序列化里的路径字段（MA / 换装组件等） | 相关配置可能失联 | 注意 |

**如果不点预检就直接「应用改名」，工具会自动先跑一次**，发现危险引用会弹窗拦一下让你确认。

> 按对象引用（fileID）绑定的东西不会断，所以不报警——绝大多数 Unity 组件都属于这一类。

### 4. 应用改名
点 **「应用改名」**：

- 场景里的对象 → 标记为 dirty，**按 Ctrl+S 保存场景**才落盘
- Prefab 资源里的对象 → 自动保存到磁盘

改错了点 **「撤销改名」** 还原，或直接 Ctrl+Z。

## 四、其它按钮

| 按钮 | 作用 |
|---|---|
| **只用术语表** | 完全不联网，只用内置词表翻译。常见服装部件基本够用，不花额度。 |
| **导出对照表 CSV** | 导出「原名,译名」，UTF-8 带 BOM，Excel 直接打开不乱码。 |
| 每行的 **「清」** | 清空该行译文，下次翻译重新处理。 |
| 每行的 **「×」** | 从列表移除，**不会**改名。 |

## 五、换用其他翻译服务

接口是 **OpenAI 兼容格式**，只要服务商支持 `/v1/chat/completions`，填上就能用：

- DeepSeek：`https://api.deepseek.com/chat/completions` + `deepseek-flash`
- OpenAI：`https://api.openai.com/v1/chat/completions` + `gpt-4o-mini`
- 各类中转站：填它给的完整地址和模型名

接口地址不是这种格式的（百度、有道、DeepL 原生 API）不支持——它们的签名和报文格式各不相同。

## 六、注意事项

1. **不会改文件名。** 只改 GameObject 的层级名（`target.name`），绝不调用 `AssetDatabase.RenameAsset`。把 `.fbx` 拖进来也只会取到它的根节点。
2. **缓存位置**：工程根目录 `Library/LevelNameTranslator/`，不进版本管理，删掉也不影响使用。
3. **翻译质量**：日文服装词比英文准（内置术语表覆盖常见部件）；专有名词可能翻得怪，**应用前扫一眼，不对的直接在输入框里改**。
4. **每批数量**默认 24。经常碰到 HTTP 429（限流）就调到 10。
5. **撤销范围**：「撤销改名」只记录**本窗口点过「应用改名」**的操作，手动在 Hierarchy 里改的名字它不管。

## 七、常见问题

**Q：测试连接报 401？**
Key 不对，或这个地址的服务不认这个 Key。检查地址和 Key 是不是同一家的。

**Q：报「model not found」之类的模型错误？**
模型名写错了，大小写敏感。照服务商文档里的 id 原样填。

**Q：报 404？**
接口地址填错了，必须是以 `/chat/completions` 结尾的完整 API 地址。

**Q：报「连不上服务器（没有收到任何响应）」？**
可能是断网、代理/VPN 拦截、防火墙或证书校验。如果开着代理软件，试着把 `api.deepseek.com` 设为直连，或临时关掉代理再测。

**Q：报 429？**
限流或额度用尽。调小「每批数量」，或换时间段。

**Q：翻译部分是空的？**
模型没按格式返回时会自动逐条重试。仍失败的条目状态显示「翻译失败」，再点一次「开始翻译」即可——已成功的不重翻。

**Q：改了名之后动画不动了？**
说明这个层级被动画路径绑定了，预检本该拦你。用「撤销改名」还原，然后只改不影响动画的部分。
